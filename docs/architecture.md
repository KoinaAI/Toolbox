# 架构与扩展边界

## 本次范围

先交付可浏览、可搜索、可收藏的目录站点和统一的工具工作区。工具标题与简介均来自 Go 目录 API。暂不提供转换、生成、检测等实际工具算法，也不伪装为已经可用。

## 目录与执行分离

分类和工具采用稳定的 slug ID，通过 `categoryId` 关联。工具拥有 `title`、`shortDesc`、`tags`、`icon`、`status` 等元数据。目录从内嵌 JSON 加载，启动时验证 ID 唯一性、分类引用与必要字段。新增条目只需修改目录文件；新增分类不需要修改页面分支。

前端的工具模块注册表按工具 ID 惰性加载，实现统一的 `ToolWorkspaceProps` 接口。目录收录与功能上线互相独立：没有模块的工具始终显示待接入工作区，不会出现虚假的执行按钮。未来后端执行接口放在独立的 `/api/v1/tools/{id}/…` 命名空间，不把算法塞进目录服务。

## 边界与存储

Go 负责目录与静态站点，同源部署不需要 CORS。Vite 开发代理转发 `/api`。目录请求支持 AbortSignal，失败时提供明确的重试入口。收藏、最近打开与主题偏好保存在当前浏览器，处理存储禁用与不合法历史数据；无登录、无云同步、无数据库。

## 交付顺序

1. 目录合约与 Go 服务。
2. 设计系统、目录页与响应式导航。
3. 搜索、收藏、工作区与键盘体验。
4. 容器、CI、GHCR 镜像与交付文档。

每项采用独立功能提交。只运行与变更直接相关的检查；最终做一次桌面、移动端和容器集成验收。
