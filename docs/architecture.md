# 架构与扩展边界

## 本次范围

目录与统一工作区包含 27 个可用工具。标题与简介由 Go 目录 API 提供；文本转换、生成、日期计算和格式化在浏览器执行，DNS/IP/HTTP 与图片处理使用同源服务端接口。

## 目录与执行分离

分类和工具采用稳定的 slug ID，通过 `categoryId` 关联。工具拥有 `title`、`shortDesc`、`tags`、`icon`、`status` 等元数据。目录从内嵌 JSON 加载，启动时验证 ID 唯一性、分类引用与必要字段。新增条目只需修改目录文件；新增分类不需要修改页面分支。

前端按工具 ID 惰性加载模块，统一实现 `ToolWorkspaceProps`。工具自身维护输入、选项与输出；公共表单、复制、错误和加载状态在 `shared.tsx` 复用。只发布 `available` 条目，合约测试保证每条都有注册实现。未知或加载失败模块显示错误状态，不显示虚构的工作区。

Monaco 编辑器、JSON 语言服务及 Worker 均为本地资源，模型和监听器在卸载时释放。JSON 格式化通过 token 编辑保留大整数；SQL 按选定方言格式化。正则与格式化使用可终止 Worker，限制输入大小与执行时间。

## 边界与存储

Go 同源托管前端与 API，Vite 开发代理转发 `/api`。收藏、最近打开和主题偏好保存在当前浏览器；工具输入与输出不持久化，无账号、云同步或数据库。

`internal/safehttp` 为每次出站连接解析并校验所有目标 IP，连接已验证地址，排除专用、回环、保留和地址翻译段；不使用环境代理，不跟随重定向。HTTP 请求限时、限请求/响应大小；IP 地理信息仅向固定的 ipwho.is 查询并缓存六小时。

`internal/imaging` 使用私有临时目录、受限输入格式、像素/文件/时长限制及固定 FFmpeg 参数，不接受命令或远程媒体 URL。仅输出静态首帧，移除元数据；任务完成、失败、取消均清理临时文件。Compose 保持非 root、只读根目录，用限额 tmpfs 提供临时工作空间。

## 交付顺序

1. 按算法、编辑器、网络与图片处理拆分功能提交。
2. 对变更所属模块运行相关检查。
3. 用真实输入验收桌面、移动端和容器工作区。
4. 集成后按新版本执行完整验证，发布不可变 GHCR 标签与 digest。

每项采用独立功能提交。只运行与变更直接相关的检查；最终做一次桌面、移动端和容器集成验收。
